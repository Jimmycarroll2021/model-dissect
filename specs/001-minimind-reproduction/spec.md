## User Scenarios & Testing

### User Story 1 - See what can be inferred from the artifact (Priority: P1)

Jimmy can follow a weight tensor into a proposed operation and through a model dataflow map,
seeing which facts were observed, inferred, supplied, contradicted or remain unknown.

**Why this priority**: This turns opaque weights into an inspectable engineering artifact.
**Independent Test**: An evaluator traces each map assertion to its allowed evidence, then
compares the frozen map with the withheld reference and reports correct, incorrect and
unresolved claims separately.

**Acceptance Scenarios**:
1. Given an identified checkpoint, when its map is produced, every tensor is accounted for
   and every claimed operation/connection has evidence and an uncertainty label.
2. Given ambiguous shapes or misleading names, when more than one computation fits, the
   map retains the alternatives until a distinguishing observation resolves them.
3. Given unavailable execution observations, structural findings remain useful but the
   executable reconstruction and internal mechanism remain explicitly unverified.

### User Story 2 - Test the reconstructed computation (Priority: P2)

Jimmy can inspect and edit the reconstructed computation, and see whether it reproduces
reference internal values and outputs on inputs it was not built against.

**Why this priority**: Matching measured computation distinguishes a plausible diagram from
an executable reconstruction within a stated test scope.
**Independent Test**: A separate evaluator compares the frozen reconstruction and reference
on the parity suite without using the reference forward computation inside the candidate.

**Acceptance Scenarios**:
1. Given a frozen map and reconstruction, when parity is measured, every required comparison
   passes R2 or is recorded as a failure; no wrapper around upstream forward counts as reconstruction.
2. Given a mismatch, when localized to a boundary, the report preserves the failure and
   narrows the unsupported claim without silently changing acceptance.

### User Story 3 - Explain one internal observation (Priority: P3)

Jimmy can examine one proposed relationship between an internal component and a measured
output, including a predicted effect, a controlled intervention and restoration.

**Why this priority**: This begins investigation of inner workings beyond tensor inventory.
**Independent Test**: The evaluator reproduces the preregistered probe on held-out inputs,
with no-op, matched control and restoration, and checks the resulting claim against R3.

**Acceptance Scenarios**:
1. Given a frozen hypothesis at an internal site, when measurements complete, the report
   distinguishes supported, refuted and inconclusive outcomes with all arm results.
2. Given correlation or general output damage alone, the report makes no causal circuit claim.
3. Given restoration, original artifact hashes and baseline numerical outputs are recovered.

### Edge Cases

- Missing/mismatched weights, tokenizer, configuration or reference identity: stop dependent checks.
- Unsupported format, tied/shared parameters, extra tensors or ambiguous orientations: enumerate
  and explain; never silently discard or invent a connection.
- Missing internal observation access: report the blocked claim and retain structural findings.
- Nonfinite results, invalid masks, context overflow or tokenizer disagreement: explicit failure.
- Oracle leakage or changed candidate: invalidate affected inference/evaluation evidence.
- Resource exhaustion or competing workload: stop owned work and preserve partial receipts.
