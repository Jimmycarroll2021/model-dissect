# Local workflow contract (implementation target)

Expose `python -m minimind_re` through project-local PYTHONPATH or installation. CLI subcommands: `inventory --manifest PATH --output PATH`; `map --inventory PATH --ledger PATH --output PATH`; `forward --protocol PATH --inputs PATH --output PATH`; `probe --protocol PATH --inputs PATH --output PATH`. Oracle has separate `python -m oracle.evaluate --candidate-manifest PATH --protocol PATH --output PATH`; it imports the candidate only for comparison, while candidate never imports oracle. Paths are explicit; no network at forward/probe time. Manifest/protocol validation failure exits nonzero before tensor execution. A failed numerical comparison exits nonzero and still writes its receipt.

Runtime guard accepts role, immutable run id, expected token spend, cumulative ledger, deadline and command argv. Reserve projected cost before launching; reconcile actual cost afterward. CPU fallback is protocol-selected before running; never mix oracle/candidate backends. All output directories are new per run ID. Existing incomplete runs require reconciliation before retry.

Inputs: token IDs [batch,sequence], boolean attention mask, explicit real-token position IDs, optional cache and continuation IDs. Padding outputs excluded only by the declared mask; real-token outputs retained. Oracle/candidate cache layouts may differ internally but must expose equivalent continuation behavior. Outputs: full logits, embedding/block/final captures and continuation/full-sequence comparison metadata. Internal site correspondence is frozen before held-out execution. No hidden target source, module tree or graph is delivered with allowed observations; expose only declared values and record architecture-bearing names/shapes as disclosures.

Each reference query logs request hash, input/observation budget, exposed sites, response hash and purpose. Reconstruction freeze (T016) fixes the map, forward computation and candidate identity before R2 parity. After passing reconstruction parity, the single preregistered development observation pass (T017) may run solely to select the internal probe; these observations must not change the frozen reconstruction. Probe freeze then fixes the hypothesis, site, perturbation, matched control, metrics, effect threshold and decision rule before any probe arms or held-out probe evaluation (T018–T019). Held-out material remains evaluator-owned. These distinct freezes do not authorize extra development passes or relax any shared resource/retry cap. No opportunistic extra oracle queries after a mismatch: preserve failure, diagnose, then use at most the single remaining retry with revised identity/fresh held-out fixtures. Runtime accounting covers both candidate and reference calls and repeated prefixes.
